# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this repo is

The procedural **art pipeline** for a Godot 4.7 multiplayer anime life-sim
(powers, magic, swords and gear). Every model here is *generated by a Python
script* that runs Blender's `bpy`, then exported to `.glb` for Godot. Nothing
is hand-sculpted: to change a model, change its build script and rebuild.

The game project itself (`life-sim-prototype`) lives elsewhere; see
`docs/LOCAL_CLAUDE_PROMPT.md` for how assets get copied into it.

**Art style:** Dragon Quest shapes (chunky, rounded, big heads, stubby limbs,
big round eyes) with Simpsons-style color (bright, flat, slightly off
cartoon colors) and thick black outlines. Colors are vertex colors; the
outline is an inverted-hull `next_pass` material.

## Conventions (important)

- **Units:** meters. Blender is Z-up.
- **Facing: models face +Z in Godot.** Scripts *model* facing +Y in Blender
  with +X as the model's right, and `face_plus_z()` (in
  `pets/build_pets.py`) turns the whole scene 180° about Z right before every
  export, baked into mesh and bone data. Every exporter must call
  `face_plus_z()` just before `bpy.ops.export_scene.gltf`. `monsters/` flips
  at build time instead (its `FLIP` matrix) and must *not* call it. The
  `.blend` files saved next to the `.glb`s are pre-flip working files.
- **Origin:** bottom center (feet on y = 0), except wall items (origin at the
  back) and doors/gates (origin at the hinge). READMEs say which.
- **Vertex colors:** one point-domain `BYTE_COLOR` attribute named `Col`,
  painted with `paint(obj, fn(co, normal))`. Paint *before* decimating.
  Sharp color details should be separate geometry (a strip, a disc), not
  vertex color, because vertex colors blur across faces.
- **Materials:** exported with a vertex-color material; in Godot use the
  toon `.tres` in each folder (thick outline for big things, thin for small).
- **Special meshes:** `glow` (eyes, emissive), `screen` (TVs and monitors,
  for a ViewportTexture) are kept as separate child meshes on export.
- **Rigs:**
  - Humanoids (`characters/`) use Godot humanoid bone names (`Hips`,
    `Spine`, `Chest`, `UpperChest`, `Neck`, `Head`, `LeftUpperArm`...) so
    Mixamo/humanoid animations retarget.
  - Pets and farm animals use a quadruped rig (`pelvis`, `spine`, `chest`,
    `neck`, `head`, `jaw`, `ear.R/L`, `upper_arm.R/L`... `tail_1..5`) with a
    looping `idle` action.
  - Monsters each have their own rig and several actions (`idle`, `walk`,
    `attack`), exported as NLA tracks.
  - `.R` / `Right` is the model's own right side.
- **Weights:** humanoid bodies use Blender automatic weights; clothing copies
  weights from the body (`copy_weights`); rigid parts use `set_weights`.
  Monsters use nearest-bone weights (`skin()`), which never fail on
  disconnected parts.

## Environment

- Blender as a Python module: `pip install bpy` (Python 3.13). Import `bpy`
  before `bmesh`/`mathutils`. Run scripts from their own folder:
  `cd monsters && python build_monsters.py goblin`.
- Or with Blender: `blender --background --python monsters/build_monsters.py -- goblin`.
- Godot 4.7 for previews: `GODOT=/path/to/godot tools/preview/render.sh out.png "monsters/goblin.glb:0:0"`.
  Headless machines need `xvfb-run` (the script uses it automatically) and a
  Vulkan driver (`mesa-vulkan-drivers`).

## Workflow for changing or adding an asset

1. Edit the build script (or add a function and register it in the
   script's `PROPS` / `MONSTERS` / `ANIMALS` table).
2. Rebuild just that asset, e.g. `cd props && python build_house_props.py sofa`.
3. **Look at it**: render with `tools/preview/render.sh` from the front
   (camera at +Z looking at the origin) and from an angle. Check facing,
   scale against `characters/hoodie_guy.glb` (1.78 m), outlines and colors.
   For rigged assets, also render a frame mid-animation.
4. Update the folder README (sizes, notes, preview image) and commit the
   script, `.glb` and preview together.

Build times: props take seconds each; pets, farm animals and monsters about
a minute each; the beastfolk kit about 10 minutes per body.

## Gotchas

- `surface_point()` / `face_point()` ray-cast the *whole scene*; build the
  body first and place eyes before adding other parts in front of it.
- `pets/build_pets.paint()` reuses an existing `Col` attribute; imported
  meshes can carry their own color attributes, which `load_base` clears.
- Remesh (`remesh_and_smooth`) fuses blobs; add pointy parts (ears, spikes)
  *after* smoothing so they stay sharp.
- Keep triangle counts reasonable: characters ~20-45k, monsters/animals
  ~15-25k, props usually under 5k. Use `limit()` / `faces=` caps and
  `segments=1` on small bevels.
- Don't commit `.blend1`, `__pycache__`, `*.import`, `tools/preview/assets/`.
